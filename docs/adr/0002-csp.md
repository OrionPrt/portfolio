# ADR-0002 — Content Security Policy strategy

- **Status:** Accepted — report-only from P0, enforced since the end of P3 (2026-10-25), before the first user-input surface (contact form, P4)
- **Date:** 2026-10-23, updated 2026-10-25 (enforcement, contact form)

## Context

A strict Content Security Policy is the main browser-side defence against XSS and a visible marker of a security-minded site (target: A+ on Mozilla Observatory). Next.js 16.4 constrains the options (bundled guide `node_modules/next/dist/docs/01-app/02-guides/content-security-policy.md`):

- A nonce-based CSP requires **every page to be rendered per request**: static pages are generated at build time, when no nonce exists.
- **Partial Prerendering is incompatible with nonces**: the prerendered static shell would carry unsigned scripts. `cacheComponents` (enabled by the 16.4 template and announced as the default of the next major) implies PPR.
- Next.js reads the nonce from the `Content-Security-Policy` request header, **or from `Content-Security-Policy-Report-Only`** (verified in `next/dist/server/route-modules/app-page/parse-request-headers.js`), and signs its framework scripts, page bundles and inline RSC payloads with it.

## Decision

1. **Nonce-based CSP generated in `src/proxy.ts`** for every request: 128 bits from the platform CSPRNG, base64-encoded, validated before being written to the header (`src/lib/csp.ts`). The policy is set on the response and on the forwarded request so Next.js can sign its scripts; any client-supplied CSP request header is deleted first, because Next.js would otherwise read it instead of ours. The matcher **fails closed**: only build assets (`/_next/static/`, `/_next/image`), and a short list of exact files (`favicon.ico`, `robots.txt`, `sitemap.xml`) are excluded. A file extension never exempts a path (`/projets/x.svg` can be a page). Prefetches stay covered as well: browser document prefetches (`Purpose: prefetch`) can be reused for a navigation, and in-app router prefetches need the proxy so next-intl rewrites their localized pathnames (skipping them cached a 404 for `/fr/projets/x`, found by the P1 E2E suite).
2. **Whole-app per-request rendering**: the root layout exports `instant = false` and reads the request headers (`headers()`, which also yields the nonce), which opts out of the static shell (the documented "allow blocking route" escape hatch). Data access stays cheap through `"use cache"` + `cacheTag` (from P2).
3. **Policy**:

   | Directive                   | Value                                                          | Why                                                                            |
   | --------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------ |
   | `default-src`               | `'self'`                                                       | Deny by default                                                                |
   | `script-src`                | `'self' 'nonce-…' 'strict-dynamic'` (+ `'unsafe-eval'` in dev) | Only signed scripts, and the chunks they load; React needs eval in dev only    |
   | `style-src`                 | `'self' 'unsafe-inline'`                                       | React `style` attributes and animations cannot carry a nonce                   |
   | `img-src`                   | `'self' data: blob: https://*.public.blob.vercel-storage.com`  | Vercel Blob serves the image library (P6c): images only, any store's subdomain |
   | `font-src` / `connect-src`  | `'self'`                                                       | Fonts are self-hosted by `next/font`; analytics beacons are same-origin        |
   | `frame-src`                 | `https://challenges.cloudflare.com`                            | The Turnstile widget's iframe (P4, [ADR-0005](0005-contact-form.md))           |
   | `object-src` / `base-uri`   | `'none'`                                                       | No plugins; no `<base>` hijacking                                              |
   | `form-action`               | `'self'`                                                       | Forms cannot post elsewhere                                                    |
   | `frame-ancestors`           | `'none'`                                                       | No framing (clickjacking)                                                      |
   | `upgrade-insecure-requests` | enforced production only                                       | Ignored in report-only mode and breaks plain-http localhost                    |

4. **Report-only first, then enforced**: `CSP_MODE` was `"report-only"` until the end of P3 and is `"enforce"` since, together with a reporting endpoint (below), so the public site never ships a form, a login or an upload behind a policy that only observes. Third parties added later (Turnstile in P4, Blob images in P6) are allowed as they arrive, under the enforced policy. A unit test pins the current mode so any change is a deliberate, reviewed one.
5. **Static headers** (HSTS, `nosniff`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, COOP `same-origin`, CORP `same-origin`) are set for every path in `next.config.ts` from `src/lib/security-headers.ts`, and `X-Powered-By` is disabled.
6. `partialPrefetching` stays enabled, as the docs require it alongside `cacheComponents`, but has no effect while the root layout opts out of the static shell.

## Proxy hardening (P1)

The proxy also runs next-intl's locale routing (ADR-0003). Composing the two added these guarantees, each covered by unit tests:

- **Fail closed on the renderer.** Any response that lets Next.js render (`x-middleware-next` or a rewrite) must forward our nonce, otherwise the proxy answers `500`. This guards next-intl code paths that skip our headers, such as its early return on undecodable paths.
- **Undecodable paths** are refused with `400`, and **methods** other than `GET`, `HEAD` and `POST` with `405` (`TRACE` used to crash the proxy). Both still carry the CSP header.
- **Paths outside the locale tree** (`/api/`, `/_vercel/`, `/.well-known/`, `/assets/`) get the CSP but no locale redirect. Files in `public/` must therefore live under `public/assets/`. Since P3, under `/api/` and `/.well-known/` only the paths listed in `src/lib/non-localized-routes.ts` reach Next.js (a unit test compares the list with the route handlers of `src/app/api`); any other path gets the proxy's 404 page, because the default one of Next.js ships unsigned scripts.
- **Locale redirects** are `private, no-store` and `Vary: Accept-Language, Cookie`. The `NEXT_LOCALE` cookie is `Secure`, `SameSite=Lax`, kept for a year (not `HttpOnly`: next-intl updates it client-side). next-intl's `Link: hreflang` header is disabled because it trusts `X-Forwarded-Host`; hreflang will come from page metadata (P3).

## Enforcement (P3)

- **Reporting.** The policy ends with `report-to csp-endpoint; report-uri /api/csp-report`: `report-to` for browsers with the Reporting API, named by the static `Reporting-Endpoints: csp-endpoint="/api/csp-report"` header, and `report-uri` for the others (Firefox). `src/app/api/csp-report/route.ts` accepts both formats (`application/csp-report`, `application/reports+json`), reads at most 64 KB, keeps the CSP violations of a batch (at most 50), caps every field at 512 characters, strips query strings and fragments from URLs (tokens, personal data), and logs one `csp.violation` warning per violation through the redacting logger. It answers `204`, or `400`, `413` and `429`, which browsers ignore.
- **Rate limit, in memory.** 20 reports per minute per client address and 600 per minute overall, per server instance, with a bounded number of tracked addresses (`src/lib/rate-limit.ts`). Abuse of this endpoint only produces log noise, so a best-effort limit is enough. It stays in memory on purpose (decided on 2026-10-25): the contact form's limit is shared through Upstash ([ADR-0005](0005-contact-form.md)), and the free Upstash quota is kept for it.
- **Vercel toolbar.** `vercel.live` injects a script and an iframe into preview deployments, which the policy would block. The toolbar is disabled in the Vercel project settings (decided on 2026-10-23) rather than allowed in previews: the policy stays identical in every environment.
- **What carries no nonce.** JSON-LD blocks (`type="application/ld+json"`) are data, never executed, so CSP does not apply to them. The proxy's 404 page (ADR-0003) has no script. Two static fallbacks of Next.js do ship unsigned scripts, which the policy now blocks: `_global-error.html` (shown only if the root layout crashes) and the default not-found page, still served for unknown paths under `/assets/` and `/_vercel/`. Both display their static HTML: they fail closed, and may surface in the violation reports.

## Alternatives considered

- **`script-src 'unsafe-inline'`** (CSP without nonce): keeps static rendering but provides almost no XSS protection. Rejected.
- **Experimental SRI / hash-based CSP** (`experimental.sri`): keeps static generation and CDN caching, but is experimental and does not cover dynamically generated scripts. To be reassessed if per-request rendering costs too much (TTFB, Vercel Hobby limits).
- **`style-src` with a nonce**: would block every React `style` attribute. Mozilla Observatory does not penalise `'unsafe-inline'` confined to `style-src`.

## Consequences

- HTML is never cached by the CDN; every page view invokes a function. Acceptable at portfolio traffic, and to be measured (TTFB, Lighthouse) from P3.
- Verification is automated:
  - unit tests: nonce entropy and format, header-injection guard, directive values, proxy forwarding, forged-header stripping and fail-closed matcher;
  - E2E tests on the production build: every `<script>` carries the per-request nonce, the nonce rotates, a forged CSP request header changes nothing, prefetched documents and extension-suffixed paths are covered, a normal visit raises no violation, and an injected inline event handler (the classic XSS vector) **is** flagged.
- Chrome exempts code evaluated through DevTools (and therefore Playwright's `page.evaluate`) from CSP: negative tests must trigger their payload through a browser-fired event.

## Contact form (P4)

- **Turnstile.** Under `'strict-dynamic'`, host sources in `script-src` are ignored. Cloudflare's script is added by our code, which `'strict-dynamic'` trusts, and carries the nonce (read from the `x-nonce` request header) for browsers without `'strict-dynamic'`. Its iframe is allowed by `frame-src https://challenges.cloudflare.com`; `script-src` lists no host.
- **Probes count as violations.** A library that tries `eval` or `new Function` raises a report even when it catches the error. Zod 4 does so when a schema is built, so Zod stays out of browser bundles ([ADR-0005](0005-contact-form.md)). The E2E suite records violations on the contact page, while Turnstile runs.

## Production check (2026-10-25)

On the Vercel deployment, HTML responses carry `x-vercel-cache: HIT`. It refers to the prerendered shell that Cache Components resumes, not to the HTML sent, which is rendered per request. Checked on production: the nonce in the body equals the one in the header on every request, and changes between requests.
