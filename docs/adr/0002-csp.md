# ADR-0002 — Content Security Policy strategy

- **Status:** Accepted — report-only since P0, enforced at the end of P3, before the first user-input surface (contact form, P4)
- **Date:** 2026-10-23

## Context

A strict Content Security Policy is the main browser-side defence against XSS and a visible marker of a security-minded site (target: A+ on Mozilla Observatory). Next.js 16.4 constrains the options (bundled guide `node_modules/next/dist/docs/01-app/02-guides/content-security-policy.md`):

- A nonce-based CSP requires **every page to be rendered per request**: static pages are generated at build time, when no nonce exists.
- **Partial Prerendering is incompatible with nonces**: the prerendered static shell would carry unsigned scripts. `cacheComponents` (enabled by the 16.4 template and announced as the default of the next major) implies PPR.
- Next.js reads the nonce from the `Content-Security-Policy` request header, **or from `Content-Security-Policy-Report-Only`** (verified in `next/dist/server/route-modules/app-page/parse-request-headers.js`), and signs its framework scripts, page bundles and inline RSC payloads with it.

## Decision

1. **Nonce-based CSP generated in `src/proxy.ts`** for every request: 128 bits from the platform CSPRNG, base64-encoded, validated before being written to the header (`src/lib/csp.ts`). The policy is set on the response and on the forwarded request so Next.js can sign its scripts; any client-supplied CSP request header is deleted first, because Next.js would otherwise read it instead of ours. The matcher **fails closed**: only build assets (`/_next/static/`, `/_next/image`), a short list of exact files (`favicon.ico`, `robots.txt`, `sitemap.xml`) and in-app router prefetches (`next-router-prefetch`, which return flight data) are excluded. A file extension never exempts a path (`/projets/x.svg` can be a page), and browser document prefetches (`Purpose: prefetch`) stay covered since they can be reused for a navigation.
2. **Whole-app per-request rendering**: the root layout exports `instant = false` and awaits `connection()`, which opts out of the static shell (the documented "allow blocking route" escape hatch). Data access stays cheap through `"use cache"` + `cacheTag` (from P2).
3. **Policy**:

   | Directive                   | Value                                                          | Why                                                                         |
   | --------------------------- | -------------------------------------------------------------- | --------------------------------------------------------------------------- |
   | `default-src`               | `'self'`                                                       | Deny by default                                                             |
   | `script-src`                | `'self' 'nonce-…' 'strict-dynamic'` (+ `'unsafe-eval'` in dev) | Only signed scripts, and the chunks they load; React needs eval in dev only |
   | `style-src`                 | `'self' 'unsafe-inline'`                                       | React `style` attributes and animations cannot carry a nonce                |
   | `img-src`                   | `'self' data: blob:`                                           | Blob storage host added in P6                                               |
   | `font-src` / `connect-src`  | `'self'`                                                       | Fonts are self-hosted by `next/font`; analytics beacons are same-origin     |
   | `object-src` / `base-uri`   | `'none'`                                                       | No plugins; no `<base>` hijacking                                           |
   | `form-action`               | `'self'`                                                       | Forms cannot post elsewhere                                                 |
   | `frame-ancestors`           | `'none'`                                                       | No framing (clickjacking)                                                   |
   | `upgrade-insecure-requests` | enforced production only                                       | Ignored in report-only mode and breaks plain-http localhost                 |

4. **Report-only first** (`CSP_MODE = "report-only"`), switched to enforcement at the end of P3, together with a reporting endpoint, so the public site never ships a form, a login or an upload behind a policy that only observes. Third parties added later (Turnstile in P4, Blob images in P6) are allowed as they arrive, under the enforced policy. A unit test pins the current mode so the switch is a deliberate, reviewed change.
5. **Static headers** (HSTS, `nosniff`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, COOP `same-origin`, CORP `same-origin`) are set for every path in `next.config.ts` from `src/lib/security-headers.ts`, and `X-Powered-By` is disabled.
6. `partialPrefetching` stays enabled, as the docs require it alongside `cacheComponents`, but has no effect while the root layout opts out of the static shell.

## Alternatives considered

- **`script-src 'unsafe-inline'`** (CSP without nonce): keeps static rendering but provides almost no XSS protection. Rejected.
- **Experimental SRI / hash-based CSP** (`experimental.sri`): keeps static generation and CDN caching, but is experimental and does not cover dynamically generated scripts. To be reassessed if per-request rendering costs too much (TTFB, Vercel Hobby limits).
- **`style-src` with a nonce**: would block every React `style` attribute. Mozilla Observatory does not penalise `'unsafe-inline'` confined to `style-src`.

## Consequences

- HTML is never cached by the CDN; every page view invokes a function. Acceptable at portfolio traffic, and to be measured (TTFB, Lighthouse) from P3.
- Verification is automated:
  - unit tests: nonce entropy and format, header-injection guard, directive values, proxy forwarding, forged-header stripping and fail-closed matcher;
  - E2E tests on the production build: every `<script>` carries the per-request nonce, the nonce rotates, a forged CSP request header changes nothing, prefetched documents and extension-suffixed paths are covered, a normal visit raises no violation, and an injected inline event handler (the classic XSS vector) **is** flagged.
- Chrome exempts code evaluated through DevTools (and therefore Playwright's `page.evaluate`) from CSP: negative tests must trigger their payload through a browser-fired event.

## Follow-ups

- Cloudflare Turnstile (P4): under `'strict-dynamic'`, host sources in `script-src` are ignored, so its loader `<script>` must carry the nonce (read from the `x-nonce` request header); add `frame-src https://challenges.cloudflare.com` for its iframe.
- End of P3: add a reporting endpoint (`report-to` + `/api/csp-report`, rate-limited), since without it production violations stay invisible; decide on the Vercel preview toolbar (`vercel.live`); then switch `CSP_MODE` to `"enforce"` and update the E2E header name. The static `_global-error.html` fallback ships unsigned scripts and will not hydrate once enforced (fails closed): check it at that point.
