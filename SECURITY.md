# Security policy

Security is a core part of this project, and reports are welcome.

## Reporting a vulnerability

Please **do not open a public issue**. Use GitHub's private vulnerability reporting instead: go to the repository's **Security** tab, then **Report a vulnerability**.

Include what you can of:

- the affected URL, page or file;
- the steps to reproduce, and a proof of concept if you have one;
- the impact you expect.

This is a personal project maintained by one person: expect an acknowledgement within 7 days, and a status update as the fix progresses.

## Scope

In scope: this repository and the deployed portfolio site.

Out of scope:

- denial of service, load or volumetric testing;
- social engineering and physical attacks;
- vulnerabilities in third-party platforms (Vercel, Neon, GitHub…) — report those to their vendors;
- findings that only rely on outdated browsers or missing best-practice headers without a demonstrated impact.

## Safe harbour

Good-faith research that respects this policy, avoids privacy violations and service disruption, and gives a reasonable time to fix before disclosure will not lead to any complaint from the maintainer.

## Supported versions

Only the `main` branch and the current production deployment receive security fixes.
